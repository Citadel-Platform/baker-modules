# Working in this codebase

This application was generated by Citadel's Factory. `baker.lock.json` records
which module versions it was built from, what each added to `pubspec.yaml`
and shared files, and the inputs given. Read it before assuming where
something came from.

What follows is what the generated code assumes: not a style guide for the
whole world, but what this codebase already does, so a change made here reads
like the code around it.

## What Baker owns and what you own

Baker wrote the first commit and nothing after it. There is no manifest to
regenerate from and no upgrade path: **editing generated files is expected and
correct.** `baker verify` tells you a module has moved on in the catalogue; it
will not move your code, and its output is not a task list.

## The rules the generated code follows

**No invented data.** Nothing here contains made-up customers, orders, metrics
or activity. An application demonstrated with fake data is one somebody
eventually demonstrates by accident, in front of the client whose data it is
pretending to be. Empty screens use `EmptyState`.

**Four states, never one.** Every data-bound region distinguishes loading,
empty, failed and not configured (`lib/src/design/states.dart`). "Not
configured" is not an error: a build with no database and a build whose
database is down need different responses. `AsyncView` does this for a
Riverpod value. Do not collapse them into a generic failure.

**Failures read as sentences.** Throw an `AppFailure`
(`lib/src/foundation/failure.dart`); show any error through
`describeFailure`. Never render an exception's `toString` into the interface.
`ApiFailure` from the Platform API client is an `AppFailure`.

**Every route states who may open it.** `AppRoute.access` is required
(`lib/src/routing/routes.dart`). The guard denies by default and roles come
from the sign-in token's claims, set by a server, never from a document the
app can write. The screen guard is not security: enforce the same rule in
Firestore rules or the API. `test/access_test.dart` fails on a public page that
is not on its short list; add to the list only on purpose.

**Money is never a double.** Use `Money` (integer minor units and an ISO 4217
code). Parse with `Money.parse`, split with `allocate`, display with
`format`. Store `minor` and `currency`, or `toDecimalString()`.

**Tables page by cursor.** Implement `PageSource` for a collection; never read
a whole collection to show a table. Keep a table's query in the URL with
`TableQueryRoute`, and list the sortable and filterable fields: anything else
in the URL is dropped.

**Design tokens, not literals.** Spacing, radius and type from `AppTokens`;
colour from `AppColors.of(context)`, which is right in light and dark mode. A
colour written twice is a colour that will one day be two colours.

**Data classes use freezed**, except where an invariant must hold in release
builds and a `copyWith` would bypass it (`Money`). Generated files are not
committed: run `dart run build_runner build --delete-conflicting-outputs`.

**The platform address is compile-time.**
`--dart-define=CITADEL_PLATFORM_API_BASE_URL`. An application that can be
pointed at a different platform by editing a preference can be pointed at
somebody else's.

**Telemetry is off until chosen.** `Capture` defaults to `NoCapture`, which
records nothing and says so (`isRecording`). Sending a client's telemetry
somewhere is a decision with a privacy answer attached.

## Layout

```
lib/
  main.dart               starts the app; nothing else
  src/
    configure.dart        connects modules before the first frame
    app.dart              MaterialApp, light and dark themes, the router
    routing/              route table, access guard, responsive shell
    access/               sessions, access rules, safe return paths
    design/               CitadelDS v1
    foundation/           failures, window sizes, debouncing
    table/                data table kit
    money/                money, axis scaling, charts
    pages/                screens
    api/                  Platform API client
    telemetry/            the capture seam
test/                     widget and unit tests
```

## Before you finish

```
dart run build_runner build --delete-conflicting-outputs
flutter analyze
flutter test
```

Both are expected to pass on a clean generated tree. If they do not, that is a
defect in the module, not something to work around locally: say so, and it
gets fixed in `baker-modules`, where the next client also gets the fix.
